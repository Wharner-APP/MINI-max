# Сквозное шифрование в MINI max

| Тип чата | Шифрование | Что видит сервер |
|---|---|---|
| Личный чат | X25519 (общий ключ пары) + XChaCha20-Poly1305, ключи из пароля (`mmid`) | шифртекст, отправитель, время |
| Приватная группа / канал | случайный групповой ключ, обёрнут для каждого участника парным ключом | шифртекст |
| Секретный чат | X3DH + Double Ratchet, привязан к устройству, нет истории на сервере | шифртекст, ttl |
| Публичная группа / канал | нет (читаемы модераторами из консоли) | всё |
| Чат с ботом | нет (бот должен читать текст) | всё |
| Файлы в зашифрованных чатах | клиент шифрует файл случайным ключом до загрузки (`enc=1`), ключ — внутри шифрованного сообщения; миниатюра — отдельный `kind=thumb` + `meta.thumb_id` | шифрованный файл |

## Секретные чаты (X3DH + Double Ratchet)
Эталонная реализация: `tools/ratchet_ref.py` (Signal Spec: X3DH rev.1, Double Ratchet rev.1; HKDF-SHA256, XChaCha20-Poly1305).
1. Вход с `device_id` (любой стабильный идентификатор устройства). Устройство публикует ключи: `POST /api/e2e/prekeys` `{sign_pub, dh_pub, spk:{id,pub,sig}, otks:[{id,pub}]}`; подпись `spk.sig` — Ed25519 от `spk.pub`, сервер её проверяет.
2. Инициатор: `GET /api/e2e/bundle?login=` (одноразовый prekey выдаётся один раз) → считает X3DH → `POST /api/secret/create {login, device_id, init:{ik,ek,spk_id,otk_id}}`.
3. Собеседник получает чат в `/api/sync` (поле `init`), считает X3DH, инициализирует ratchet (Bob).
4. Сообщения: `POST /api/messages/send` с `enc:1`, `body` = base64(ratchet-сообщение), `ttl` = секунд до удаления **после прочтения** (таймер ведёт клиент). Сервер доставляет только на устройство-получатель.
5. После сохранения клиент вызывает `POST /api/secret/ack {ids}` — сервер удаляет сообщения. Недоставленные хранятся не дольше 30 дней (`GET /api/secret/pending`).
6. Скриншот/удаление — сообщения `kind=screenshot`. `POST /api/secret/delete` удаляет чат.
Секретные чаты не пересылаются и не попадают в облачную историю.
